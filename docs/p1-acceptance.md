# P1 统一事件与状态

日期：2026-10-11。基线：0.5.0。验收版本：0.5.1-p1。

## 实现与边界

| 模块 | 职责 |
|---|---|
| live_viewer/events.py | 不可变 v1 事件、字符串与字段过滤、JSONL 落盘与轮转、日志导出、按作用域保存故障及提醒去重 |
| live_viewer/playback.py | 不依赖 Tk / Qt 的播放会话与任务代次、播放状态、取消与恢复、后台取流准备 |
| live_viewer/relay.py | 实际预检查、候选失败、开始转发、意外中断及播放器断连事件 |
| live_viewer/app.py | 当前界面适配：有效任务回调才启动播放器；固定状态 / 告示与非阻塞提醒；账号、收藏、设置和诊断事件 |
| live_viewer/qr_dialog.py | 二维码生成、刷新、扫码、确认、过期、取消及失败；重复等待状态不刷日志 |
| live_viewer/p1_diagnostics.py | 发行包内独立离线检查 |

事件结构与 P0 规范兼容，正式事件 demo=false。房间标识为平台:房间号；同一次自动恢复保留会话 ID，每次取流使用新代次。停止、关闭、切换与新一次取流使先前结果失效。后台线程不启动 PotPlayer；当前界面回调在检查有效性后才执行播放器请求。

普通活动与当前故障分别保存。播放故障具有较高展示优先级，账号 / 设置 / 诊断的成功不能将其抹去。停止为 INFO；离线房间为 WARN / start_blocked；无法连接或启动为 ERROR；是否影响启动或已经中断与严重等级分开记录。

一轮故障首次强提醒，后续重试仍逐条记日志。恢复后解除当前告示并重新计算下一轮故障的提醒资格。未开播、登录过期不会无意义地自动重试。沿用已有无限重试策略，退避上限 30 秒；P1 不另加“最终失败”次数限制。

磁盘不可写时只产生一次日志告示，仍保留最多 2000 条内存事件供导出；写入恢复后解除告示。原始异常、请求头、Cookie 对象、媒体 / 本机地址和扫码密钥不进入日志。只保留明确允许的技术详情字段。文件轮转、历史读取和导出也经过过滤；损坏行被跳过。旧日志只供查看和导出，不重放为当前错误。

## 验证

自动验证覆盖并发写入、轮转与启动保留、损坏行、脱敏导出、磁盘失败恢复、故障提醒去重、跨操作状态、播放取消后的资源关闭，以及停止后马上发起新播放时的旧结果隔离。测试使用临时目录与合成 Cookie。

- 110 项测试全部通过（原有 88 项 + P1 新增 22 项），无跳过；包含长错误提醒的内容尺寸与恢复关闭，以及轮转文件时间戳相同的读取顺序检查。
- 源码离线自检通过：8 项 P1 检查，以及原有界面、播放器初始化、设置恢复与加密登录检查。
- 真实匿名取流：斗鱼 6657（实际房间 6979222）和 B 站 10927621 均得到 HTTP 200 / FLV，分别短时读取 512 KiB；均记录解析、预检查及转发事件。B 站指定的 1883358196 当次未成功解析，检查工具选用官方公开列表中的样本；产品本身不替换用户房间。此检查未启动 PotPlayer，也不证明画面或声音已解码。
- 发行包离线自检结果单独保存，不读取或修改真实 data。
- 原有内置播放器短时解码与受控断流恢复通过：1920×1080、D3D11 硬件解码；恢复一次，播放列表保持一项；主动停止后重试已取消。结果在 .research/p1-native-validation.json。

可重复执行：.venv-build/Scripts/python.exe tools/validate-p1.py。

实时取流验证与打包检查的具体结果在 .research/p1-validation.json、.research/p1-live-validation.json 和 .research/p1-packaged-validation.json。界面截图在 .research/p1-screenshots。

## 后续阶段

P1 仍使用原界面验证基础，不替代 P0 Qt 原型。P2 接管 PotPlayer 的实例、停止与旧源替换；P3 将 Qt 页面接入已抽出的控制器与统一事件入口；P4 完成现有功能迁移。PotPlayer 内部弹窗、全屏时后台提醒可见性及实际解码状态不在 P1 的完成项中。
