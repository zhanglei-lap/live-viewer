# P9 验收 · 抖音直播接入（0.10.0）

日期：2026-11-11。版本 0.9.0 → 0.10.0。

## 范围

P9 只做一件事：**在原有斗鱼 / B 站之外增加抖音直播**，并把平台差异从散落的二元
`if/else` 收敛为声明式注册表。不改动点播与番剧，不改变 PotPlayer 之外的播放架构。

明确**不做**的两项：

- 不做抖音扫码登录（网页登录链路签名复杂、风控严格，只支持 Cookie 导入 / 粘贴）。
- 不做 `lls` 低延迟协议。实测它是 WebRTC，迁移成本见
  [lls 迁移评估](p9b-lls-assessment.md)，结论是暂不实施。

## 平台注册表

新增 `live_viewer/platforms.py`，每个平台一个 `PlatformSpec` 声明 17 项差异。
`REFERERS` / `COOKIE_DOMAINS` / `MEDIA_DOMAINS` / `settings.PLATFORMS` 全部由注册表派生，
旧名字保留，冻结的 Tk 前端与既有测试无需改动。

消除的分支：`PlatformClient.resolve` 三元分派、`room_number` 平台分支与固定位数上限、
`login_status`、`media_urls`、Cookie 导入特判、扫码流程静默落到斗鱼分支、
账号页硬编码的登录说明与永远显示的扫码按钮。

**加入抖音时改动量：注册表加一项 + 一个取流方法 + 离线测试，UI 代码零改动。**
这本身就是注册表是否有效的检验。

## 打包后验收

对构建产物 `dist/p9/LiveViewer-0.10.0/` 做了两项独立验证，使用全新数据目录，
不触碰正常账号数据。

**1. 离线交互验证**：`LiveViewer-0.10.0.exe --validate` 退出码 0，
55 项检查全部通过，无失败项。

**2. 打包后匿名实播**（房间 `335610475439`，`--probe-live --probe-platform douyin`）：

| 项目 | 结果 |
|---|---|
| `frozen` | True（确为打包程序） |
| 实际档位 | 原画，码率 19904 kbps，AVC，**2 个 CDN 候选** |
| PotPlayer | `playing`，1920×1080，59.999 fps，`owned_source=True`，弹窗 0 |
| 进度与尺寸 | 通过 |
| 停止关闭本工具媒体 | 通过 |
| 退出响应 | 通过 |

该次实播的事件序列包含 `relay.candidate_failed` 紧接 `relay.source_ready`，
说明**主线路失败后自动切换到备用 `douyinliving.com` 主机并成功播放**。
这正是多房间验证发现、随后修复的域名白名单缺陷，在打包产物上被实际走通。

产物规模：313 个文件 / 112 MB，ZIP 47.9 MB；不含 data 与 credentials。

## 已知限制

- 延迟比抖音网页版高约 3 秒，属 FLV 协议与 PotPlayer 缓冲的固有差距，不是转发缺陷；
  **不要为降延迟关闭「PotPlayer 原生回看」**，实测反而更慢（5.0 秒）。
- 三个房间中只有房间 67876457927 做过完整真人实播；另外两个只到取流层。
- 不支持 `v.douyin.com` 分享短链，需要从浏览器地址栏取 `live.douyin.com/` 后的数字。
- 不支持扫码登录；抖音接口与风控可能随时变化，失效时日志会给出具体状态码。
- 单文件 EXE 未单独做抖音实播验收。
