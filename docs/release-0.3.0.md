# 0.3.0：房间命名与内置扫码登录

日期：2026-10-07（香港时间）。用户报告已完成 30–60 分钟稳定性与断网恢复测试，均无明显问题；用户选择下一阶段优先内置扫码登录。

后续补充：用户已反馈本版本扫码登录测试无问题，并授权继续下一阶段。内置播放及自动重连见 [0.4.0 验收](release-0.4.0.md)。

## 房间命名

观看页增加“自定义房间名”输入框，点击“保存房间”创建或更新记录。索引始终为平台 + 归一化数字房间号，显示名称不参与平台请求；相同名称可用于不同房间或平台，同一索引改名不会新增重复收藏。

名称同步到收藏、最近观看、上次房间和当前播放状态；重启后恢复。输入 06657 与 6657 归到同一索引；数字短号与真实房间号的既有收藏不做自动合并。旧版名称和设置兼容，API 取流仍使用房间号。

## 扫码登录

账号页新增“扫码登录”，两个平台均使用原生二维码窗口。使用对应平台手机 App 扫码并在手机上确认；程序只接收平台返回的 Cookie，不要求聊天提供账号密码或登录凭据。二维码过期后可刷新，关闭窗口取消本次本地流程；刷新与取消后的旧结果不会覆盖当前登录。

二维码、临时密钥和请求数据只留在内存中。成功后接入原有登录验证和“记住当前平台登录”选项；未勾选时不落盘，勾选后使用 Windows DPAPI 加密。二维码窗口与网络请求各自运行，网络线程不操作 Tk 控件。

实现依据当前平台网页流程：

- B 站：网页二维码 generate / poll；处理等待、已扫未确认、过期及成功。成功须取得 SESSDATA，随后仍通过已有 nav 接口验证登录。
- 斗鱼：scan/generateCode、japi/scan/auth；确认后请求平台 HTTPS 回调并接收 acf_auth。只解析固定 JSONP 包装，不执行服务器返回的 JavaScript。取消未完成二维码时尝试 scan/deleteCode。流程来自 [斗鱼官方登录脚本](https://shark.douyucdn.cn/app/douyu-passport/js/page/login/app-all.js?v=v202510276)。

首轮调查曾遇到 B 站 Requests TLS 连接失败，之后正常。增加只在 SSL 异常时启用的 Windows 系统 curl HTTPS 兼容通道；没有关闭证书校验。URL、临时密钥、POST 数据与 Cookie 从标准输入传给 curl，不进入进程命令行。请求及每次重定向均限制在当前平台的 HTTPS 域名。

## 验证

- 62 项自动化测试通过：房间索引与重复名称、重启命名恢复、认证状态、Cookie 域名范围、取消与刷新竞态、JSONP 解析、TLS 兼容、秘密不进入命令行，以及此前平台/转发/加密功能。
- 两个平台真实公开扫码接口均成功生成 PNG，并取得 waiting 状态；二维码没有展示或扫描，随后取消本次请求。
- B 站 Windows TLS 兼容通道单独实测生成和轮询成功。
- 房间命名页、账号页与扫码窗口已检查截图；二维码截图使用 example.invalid 的无效演示数据。
- 最终 EXE 自检检查名称恢复、二维码渲染、加密登录读写，以及两个平台生成二维码、未扫码状态与匿名直播转发。

真实手机确认后的平台回调、账号登录状态和最高画质仍需用户本机验收；二维码申请成功或未扫码状态不能代替完整登录验证。平台风控或接口变化时仍可使用 Cookie 导入。
