# 0.4.0 内置播放阶段

日期：2026-10-07（香港时间）。用户反馈上一阶段扫码登录测试无问题，继续下一阶段。此前用户已确认 PotPlayer 版 30–60 分钟稳定性和断网恢复无明显问题，但有旧源残留及报错弹窗。本阶段接入内置成熟播放引擎，同时保留外部 PotPlayer。

## 本次完成

- 默认可选内置 libmpv，独立播放窗口与主界面属于同一应用，提供暂停、继续直播、音量、静音、全屏和回到直播。
- 继续直播重新解析并回到最新位置；换流使用 loadfile replace，唯一播放项不追加旧源。错误显示在状态栏，内置模式没有旧源报错确认弹窗。
- 内置断流和持续停滞后自动重连，退避为 1、2、5、10、20、30 秒，最多每 30 秒尝试一次。重连沿用实际正在播放的房间、账号使用方式和请求档位，不读取后来编辑的房间输入。
- 停止、关闭播放窗口、退出、手动暂停或关闭自动重连会取消或抑制后续重试。异步停止完成后才提交紧接着的新加载；旧播放项的结束事件、旧一代属性回复不会污染新流状态。
- 引擎只接收本机转发地址，登录 Cookie 和签名 CDN 地址仍由平台适配器处理。用户配置、自动脚本、youtube-dl 和磁盘缓存关闭。
- 显示和报告增加解码参数、硬件解码器、播放进度、约略缓存、播放项数与重连次数。播放器报告视频输出就绪且进度推进时提供解码证据；实际声音与音画同步仍需人工确认。

## 引擎与分发

使用 [mpv 官方发布](https://github.com/mpv-player/mpv/releases/tag/git-release)的 Windows x64 LGPL 构建，版本 v0.41.0-dev-geb0ee1031，API 2.5。官方 CI 构建主要用于测试，本项目已针对实际 AVC FLV、D3D11 和 AAC 做验证。

构建入口改为 tools/build-windows.py。本机 WMI 系统信息查询出现等待，构建进程及其分析子进程启用 Python 的原生/注册表备用版本信息路径；该设置不进入应用运行环境，不修改 Windows 服务。旧 PowerShell 入口仅委托该脚本。

最终包同时排除应用运行不需要的 setuptools、pkg_resources 和 distutils 构建钩子，避免它们在启动阶段重复触发 WMI 查询。移除这些依赖后的 EXE 完整自检通过；显式 --self-test 可生成调用栈诊断，正常启动不写该诊断文件。

固定压缩包 SHA-256：25a6421b677e97160f89af4f1bde4d515e54721d7a18d2ac30c406dcf7085f86。

固定 DLL SHA-256：1a782e67d5deb4af26ecd858ea2048efb3985b9069391cdd343fd799fea0a2b5。

本体 EXE 保留单文件打包方式，引擎动态 DLL 位于 runtime/mpv/libmpv-2.dll。完整 ZIP 必须保留 runtime；许可证、来源记录和 C API 头文件一同分发，可替换为兼容库。构建脚本将依赖下载至项目 vendor 并校验摘要，不安装系统软件。

## 本机验证

- 74 项自动化检查通过，含既有账号/扫码/平台功能，以及播放项替换、停止与加载顺序、旧事件忽略、重连退避、手动停止取消、编辑其他房间不影响重连、停止后保留解码证据。
- 斗鱼 6657 实际内置播放：H.264、1920×1080、30 fps、D3D11VA 硬件解码、AAC 44100 Hz；原生视频截图确认画面已解码。约 25 秒短测播放项数为 1，未观察到解码丢帧。
- B 站 35 和用户补充房间在测试时未开播；因此只在测试工具中从官方公开直播推荐选取样本 30291463。实际内置播放为 H.264、1280×720、30 fps、D3D11VA、AAC 48000 Hz。产品播放不会自动换到其他房间。
- 控制测试主动停止本工具的转发，不关闭系统网络；内置播放器自动重新取流并恢复，播放项数仍为 1。暂停/继续、全屏/窗口和停止取消重试通过。
- 最终 EXE 检查内置库初始化、账号与房间恢复、原生解码和受控断流恢复；其他平台测试使用公开匿名流，不读取用户账号。
