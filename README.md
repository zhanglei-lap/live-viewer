# 本地直播 · Qt / PotPlayer 0.10.0

Windows 桌面观看软件，支持斗鱼、B 站与抖音直播、B 站普通视频与番剧，经本机 RTMP / HTTP 转发交给 PotPlayer。观看时无需打开平台网页，转发保持源流编码；原 Tk 版本另保留内置 libmpv 入口。

抖音为 P9 新增：在观看页选择“抖音”，输入 `live.douyin.com/<房间号>` 链接或 12–15 位房间号即可，用法见 [P9 抖音直播](docs/p9-usage.md)，取流可行性证据见 [P9-A 验收](docs/p9a-acceptance.md)。抖音只支持 Cookie 导入，不提供扫码登录。

当前 Qt 版本为 **0.10.0**（P9）：在 0.9.0 的番剧、普通视频与直播能力之上加入抖音直播，并把平台差异收敛为声明式注册表，新增平台不再需要改界面代码。便携包为 [LiveViewer-0.10.0-win-x64.zip](dist/p9/LiveViewer-0.10.0-win-x64.zip)，完整解压后运行文件夹中的 EXE。P9 范围与验证边界见 [P9 验收](docs/p9-acceptance.md)；番剧能力沿用 [P8 使用说明](docs/p8-usage.md) 与 [P8-B 验收](docs/p8-acceptance.md)。

默认 main.py、qt_main.py 和启动脚本使用 Qt，依赖 requirements.txt；Build-Live-Viewer.cmd / tools/build-p9.py 构建当前版本。Tk 入口为 legacy_main.py，之前的便携包保留。阶段交付、统一日志与通知规则见 [开发路线规划](docs/roadmap-qt-potplayer.md)。以下“启动”及后续章节保留 0.5.0 的历史功能说明，当前 Qt 支持范围以 P9 使用说明为准。源码启动 Qt 可执行 `python qt_main.py`；双击 Start-Live-Viewer.cmd 也启动当前 Qt 版本。

另提供 [0.10.0 单文件 EXE](dist/p9-single/LiveViewer-0.10.0-single.exe)，只复制它即可启动，不需要外置 runtime 或安装 Python；PotPlayer 仍需安装。构建入口为 Build-Single-EXE.cmd，使用和数据迁移见 [单文件版说明](docs/p9-single-usage.md)。文件夹版保持原样，其 EXE 必须和完整 runtime 一起复制。

P9 分两个阶段：P9-A 用独立只读探针在三个真实开播房间验证抖音取流（20/20、10/10、8/8 成功，HTTP 444 零次，无需 `a_bogus` 签名）；P9-B 完成平台注册表、抖音取流、CDN 白名单与文档。抖音的 3 秒延迟已定位为 PotPlayer 内部缓冲而非转发缺陷，见 [延迟调查](docs/p9-latency-2026-11-11.md)；低延迟协议 `lls` 实测为 WebRTC，[迁移评估](docs/p9b-lls-assessment.md) 结论是暂不实施。332 项自动检查、三档高 DPI 通过，用户确认抖音实播画面与声音正常。升级时先退出程序，把旧便携目录的 data 文件夹复制到新 EXE 旁并保留原目录。

番剧阶段按 [P8 开发计划](docs/p8-bangumi-plan.md) 完成：P8-A 的 EP 解析、代理隔离、高清对比与整集可行性通过；P8-B 已在正式 EXE 验证三部 × 两集会员实播、完整首集、切集、暂停恢复、续期及清理，用户确认内容与音画正常。296 项自动检查、三档高 DPI 与普通视频回归通过。独立 P8-A 工具及 0.8.0 稳定包保留。

P0 原生 Qt 交互原型已完成：便携包在 dist/p0/LiveViewer-P0-win-x64.zip，使用说明见 [原型入口](prototypes/p0/README.md)，设计与验收见 [P0 规范](docs/p0/design-spec.md)。原型使用演示数据；正式业务接入按后续阶段推进。

## 启动

直接双击 `dist/LiveViewer-0.5.0.exe`，无需 Python；内置播放无需安装 PotPlayer；请保留同目录 runtime 文件夹。外部播放需要本机安装 PotPlayer。当前构建适用于 Windows 11 x64，已在本机 25H2 验证。便携包为 `dist/LiveViewer-0.5.0-win-x64.zip`，解压到可写目录后运行。

源码运行：

```powershell
python -m pip install -r requirements.txt
python legacy_main.py
```

也可双击 `Start-Live-Viewer.cmd`。

## 日常观看

1. 在“观看”页选择平台、输入房间号或链接，点击“开始播放”。回车也可播放。
2. 播放方式默认“内置播放器”；也可选 PotPlayer，并在“账号与播放器”页选择已安装的 PotPlayer 程序，例如 `D:\potplayer\PotPlayerMini64.exe`。
3. 输入房间号后，在“自定义房间名”中填入名称并点“保存房间”；同一平台、同一房间号会更新原记录。名称可以重复，索引始终是平台 + 数字房间号；改名同步到收藏、最近观看和当前播放名称。选取收藏后点击“播放收藏”。
4. “最近观看”保存最近 30 个实际取到视频数据的房间；选取后可直接播放，也可清空记录。
5. 上次选择的房间、每个房间的画质与账号使用方式会记住；启动时不会自动播放。
6. “原画优先”请求 B 站 qn=10000、斗鱼 rate=0；平台可能降档，界面按实际 current_qn / rate 显示。先到“画质对比与报告”获取可选档位，再选择画质并启动播放。
7. “回到直播”恢复上次播放的房间和档位，重新解析地址并在当前内置窗口替换播放项；选择 PotPlayer 时沿用外部播放。“停止播放流”停止本机转发并取消自动重连。观看时保持工具开启。

## 登录与记住账号

在“账号与播放器”页点击“扫码登录”，使用当前平台手机 App 扫描程序中的二维码，并在手机上确认。二维码过期可刷新，关闭窗口取消本次登录；成功后程序自动接收 Cookie，B 站会再检查登录状态。

二维码和临时密钥只留在内存，刷新后的旧结果不会导入。勾选“记住当前平台登录”后，扫码取得的 Cookie 也会由 Windows 加密保存。

仍可在本机浏览器登录平台后导入 Netscape Cookie 文本或点击“粘贴 Cookie”，文本可以有后缀或无后缀。

B 站：F12 →“应用程序 / Application”→“Cookies”，找到 SESSDATA，复制 Value；工具支持只粘贴该值或完整 Cookie 请求头。

斗鱼：F12 →“网络 / Network”，刷新直播间，选择发往 douyu.com 的请求，从“请求标头 / Request Headers”复制 Cookie 的整行值，格式为 `name=value; name2=value2`。不要复制响应中的 Set-Cookie。

Edge 的 `User Data/Default/Network/Cookies` 是 SQLite 数据库，不能作为文本导入；修改后缀无效。本工具不读取或解密浏览器数据库。

“记住当前平台登录”默认关闭，未勾选时 Cookie 只保留在内存中。勾选后使用 Windows DPAPI 的当前用户范围加密保存；取消勾选删除已保存的登录，本次会话仍可使用。“清除当前平台登录”同时清除内存和保存的登录。下次启动会恢复记住的 Cookie；登录仍可能过期，B 站播放前验证登录状态，斗鱼账号有效性尚未独立验证。

凭据不写入设置、报告或播放器命令行。不要在聊天中发送密码、Cookie，也不要分享数据目录中的 credentials 文件夹。

## 数据与升级

源码使用项目内 `.local/`；EXE 使用程序同目录的 `data/`。设置包含收藏、最近观看、播放器路径、上次房间、各房间的画质与账号使用方式；加密 Cookie 单独保存在 `credentials/<平台>.dpapi`。

旧版收藏和播放器路径兼容读取。构建脚本首次生成 `dist/data/settings.json` 时会从源码设置迁移，已有 EXE 设置不会被覆盖；便携 ZIP 不包含个人设置和账号。更新 EXE 前关闭工具，保留 data 文件夹即可继续使用。

设置使用临时文件替换，写入失败保留原文件；无法解析的设置会在替换前备份为 settings-unreadable-*.bak。程序目录不可写时会明确提示。

## 内置播放器

默认使用官方 Windows x64 LGPL 构建的 libmpv。mpv 自己创建原生播放窗口，使用其内置 OSC 提供暂停、音量、静音和全屏，移除旧版 Tk 播放外壳。空格暂停 / 继续，F 或双击全屏，Esc 退出全屏，L 回到直播；关闭播放窗口停止该会话。

底部补充本次观看的缓存条，可以点击 / 拖动，在 mpv 返回的实际可用缓存内回看；左右键移动 5 秒。后向缓存内存上限 32 MiB，具体可回看秒数由码率和关键帧决定；断流或重连会清空。它不提供整场回放。继续播放会重新取流回到最新位置。

“内置播放器断流后自动重连”默认开启。断流或持续停滞时按 1、2、5、10、20、30 秒退避重新解析同一个房间；刷新时使用 replace 替换唯一播放项，不追加旧源，也不弹出错误确认对话框。新流恢复推进后退避重置。停止播放、关闭播放窗口、退出程序和手动暂停会抑制重试；取消勾选可关闭自动重连。更换观看页输入不会改变正在重连的房间。

内置播放器只接收 127.0.0.1 地址，不接收平台 Cookie 或签名 CDN 地址。配置和自动脚本加载关闭，磁盘缓存关闭，默认尝试 D3D11 硬件解码；无法加载引擎时可选择 PotPlayer。报告增加实际解码参数、播放进度、约略缓存、播放项数量和重连次数；声音与音画同步仍需人工确认。

程序本体是单文件 EXE，但内置引擎为 runtime/mpv/libmpv-2.dll，不能仅拷贝 EXE 后期待内置播放可用。共享 DLL 可由用户替换为兼容版本；来源、摘要、LGPL 许可证和 C API 头文件随 runtime 分发。

## 网络直连

在“账号与播放器 → 网络连接”选择直连（默认）或系统 / 环境代理，影响下次平台接口、扫码和 CDN 请求。直连不继承代理设置，不修改 Windows 网络配置；VPN 全局隧道仍由 Windows 决定。mpv 的本机连接始终绕过代理。

点击“检查当前直播间连接”检查平台接口与 CDN FLV 读取；随后可在报告页导出结果。失败提示区分公共主机名、DNS、TLS、代理和超时，不导出签名 URL 或凭据。所有解析发生在用户电脑，没有本项目的境外解析服务器。大陆朋友仍需在当地网络复测，技术链路与排查步骤见 [取流与网络说明](docs/playback-and-network.md)。

## 直播延迟与积压

“优先实时播放”默认开启，下次播放生效。上游读取和播放器写入分别进行，队列只保存短时数据；超过 3 秒或 8 MiB，或向播放器写入超时 3 秒时结束旧连接，提示点“回到直播”。关闭此选项恢复普通同步转发。它只限制本工具内的积压，不能自动清除 PotPlayer 内部的播放缓冲。

“回到直播”重新解析上次房间；内置模式替换当前播放项，PotPlayer 模式通过 /current /autoplay 打开新连接，适合画面落后时清除旧播放会话。暂停后也可能离开最新位置。请确认 PotPlayer 播放速度为 1.0x。

状态栏“转发进度差”表示已收到与已写出 FLV 时间戳之间的差，不是画面相对主播或网页的实际延迟。报告 timing 含收到/转发媒体时长、相对墙钟进度、写入耗时、队列峰值和积压断开次数；不读取播放器画面进度。初始服务器缓存会造成相对墙钟指标为负值，不能将其解释成绝对直播延迟。

2026-10-06 对斗鱼 6657 的原链路与新链路各做 90 秒快速消费测试，没有复现持续进度落后；用户描述的长时间 PotPlayer/网页差异尚未复现，详见 docs/latency-2026-10-06.md。

## 画质对比与诊断

“画质对比与报告”页比较匿名与导入 Cookie 会话的实际返回画质，并短时读取 FLV 元数据。报告只含实际档位、流元数据、样本码率与转发统计，不含 Cookie 或签名直播地址；用户备注按原文导出。

标称码率、短时样本码率和实际解码帧率有不同含义。容器读取不能证明解码成功，画面、声音与音画同步由用户在 PotPlayer 中确认。

斗鱼会从房间网页提取真实房间号再签名，例如 6657 对应 6979222。首线路失败时，在同一账号会话下重新签名请求平台列出的备用线路，最多额外尝试三条，只接受实际 rate 相同的返回。已适配 livehwc4.com 和 edgesrv.com；未知域名提示仅显示域名，不包含签名参数。HTTPS 证书校验保持启用。

测试覆盖房间索引、命名恢复、扫码状态与取消/刷新、平台适配、备用 CDN、报告脱敏、设置升级、原子写入、历史记录、Windows 加密、登录记忆、内置播放项替换、关闭 / 暂停 / 重连控制和代理隔离。EXE 自检使用隔离配置；`--mpv-test` 静音实播内置窗口并模拟本工具连接中断，`--live-test` 检查匿名取流，`--qr-test` 检查二维码生成和未扫码状态。B 站首选样本未开播时，自检从官方推荐选择当前开播样本并记录实际房间；产品播放不会换房间。

0.5.0 的 88 项测试及打包后自检通过；直连优先 IPv4，保留 IPv6 回退。本机斗鱼 6657 与 B 站 1883358196 已完成原生窗口短时实播和交互验证；大陆网络与长时间音画同步仍需用户实测。

## 当前限制

- 已支持内置 libmpv 与 PotPlayer、AVC / H.264 HTTP-FLV；HLS、HEVC 的平台解析尚未实现。用户已反馈上一阶段扫码登录测试无问题；自动化验证仍使用合成凭据，不读取真实账号。
- 播放途中断流需播放器重新连接，或点击“回到直播”；不向已有连接拼接其他 FLV，不保证无缝恢复。
- 用户于 2026-10-07 报告已完成 30–60 分钟稳定性与断网恢复测试，均无明显问题；这是用户实测反馈。尚未在未安装 Python 的另一台干净机器验收。
- 网页直播接口可能变化，需要维护适配器。

详细资料见 `docs/research-2026-10-05.md`、`docs/prototype-validation.md`、`docs/release-0.5.0.md` 和 `docs/playback-and-network.md`。

扫码接口使用平台当前的网页流程，可能受风控和接口变化影响。遇到 Python TLS 连接问题时使用 Windows 自带 curl 的 HTTPS 兼容通道，证书校验始终开启，登录 URL、密钥与 Cookie 通过标准输入传递，不进入命令行。

内置模式已经采用唯一播放项替换和无模态错误处理；PotPlayer 自身的旧源残留和错误弹窗行为仍保留，不修改用户播放器全局配置。内置引擎的 30–60 分钟持续播放、声音与音画同步仍需用户本机验收。

构建会下载并校验固定官方 LGPL 引擎（只保存到项目 vendor 目录）。EXE 自检 --mpv-test 静音实播并模拟本工具连接中断，不关闭系统网络；源码运行此检查前需执行 tools/fetch-mpv.py。
